## 一、背景与动机

### 1.1 从 M8 到 M9：为什么需要三层

M8 实现了"优雅记忆命中"——多层检索引擎（直接命中 → 扩散联想 → 语义检索 → 消化产物）。但测试暴露了一个结构性问题：

| 问题 | 表现 | 根因 |
|------|------|------|
| 扩散淹没直接命中 | "百年孤独"返回的第一条是"我是小砂锅" | `用户` 节点是星形枢纽，任何扩散都经过它 |
| 语义匹配失效 | "记忆"查不到"记住的只有零散的碎片" | 字面匹配和语义匹配没有分层 |
| 所有边长一样 | 问候、身份、知识全混在一张图里 | 图没有区分边的性质 |

> **通俗解释**：M8 就像把所有东西——购物清单、家人的电话号码、中学学过的物理公式——全部塞进一个抽屉。你要找"马尔克斯是谁"，结果先翻出来的是"早上好"和"你的名字是什么"。不是东西丢了，是分类错了。

### 1.2 设计原则：映射又独立

人类记忆天然分为三种，认知科学中称为：

- **情节记忆（Episodic）**：什么时候发生了什么 → **时间链**
- **社会记忆（Social）**：谁是谁，什么关系 → **身份关系**
- **语义记忆（Semantic）**：概念和概念之间的关联 → **知识网**

三者互相映射（共享节点名），但独立运作（检索时走各自的子图，互不污染）。

> **通俗解释**：你记得"上周二和同事聊了马尔克斯"（时间链），也记得"马尔克斯写了《百年孤独》"（知识网），还知道"同事叫小王"（身份关系）。这三个记忆是分开的——你问"上周二聊了什么"不会先回答"马尔克斯是谁"，你问"马尔克斯是谁"也不会先说"上周二"。但"马尔克斯"这个词同时出现在三个记忆里，所以它们能互相引用。

## 二、技术架构

### 2.1 三层定义

```
┌─────────────────────────────────────────────────────┐
│                                                       │
│   时间链 (timeline)                                    │
│   ─────────────────                                   │
│   类型: 单向链表                                       │
│   边: "先发生 → 后发生"                                │
│   回答: "什么时候"                                     │
│   检索: 沿时间回溯                                     │
│   示例: 问候 → 百年孤独 → 推荐 → 晚安                 │
│                                                       │
│   身份关系 (identity)                                  │
│   ─────────────────                                   │
│   类型: 有向关系图                                     │
│   边: "A 是 B" / "A 属于 B"                           │
│   回答: "谁是谁"                                       │
│   检索: 精确匹配                                       │
│   示例: 小砂锅 → 用户, 藤蔓 → AI, 马尔克斯 → 作者     │
│                                                       │
│   知识网 (knowledge)                                   │
│   ─────────────────                                   │
│   类型: 无向关联图                                     │
│   边: "A 关联 B"                                       │
│   回答: "什么关联什么"                                  │
│   检索: 扩散激活                                       │
│   示例: 百年孤独 ↔ 马尔克斯 ↔ 魔幻现实主义             │
│                                                       │
└─────────────────────────────────────────────────────┘
```

### 2.2 实现要点

| 组件 | 之前（M8） | 之后（M9） |
|------|----------|----------|
| **M3 解析器** | 只输出 `action`/`target` | 增加 `edge_type`: `timeline`/`identity`/`knowledge` |
| **M4 图引擎** | 所有边混在同一个图 | `TypedTrace` 带 `edge_type`，支持按类型提取子图 |
| **M8 检索引擎** | 单图扩散，`用户` 污染一切 | `ThreeLayerRecall`：三路并行，各走各的子图 |
| **扩散激活** | 无方向限制 | `spread_activation(node, edge_type)` 只在指定类型子图上扩散 |

### 2.3 检索流程

```
用户查询: "百年孤独"
    │
    ├──→ 知识网检索: _find_nodes("百年孤独") → 种子节点
    │       │
    │       ├── 直接命中: 种子节点自身的 knowledge 边
    │       └── 扩散激活: spread_activation(seed, "knowledge", depth=2)
    │
    ├──→ 身份关系检索: _find_nodes("百年孤独") → 种子节点
    │       └── 精确匹配: 种子节点自身的 identity 边
    │
    └──→ 时间链检索: _find_nodes("百年孤独") → 种子节点
            └── 精确匹配: 种子节点自身的 timeline 边

    → 三路结果合并，按权重组装
```

> **通俗解释**：每次查询，系统同时走三条路——知识网、身份关系、时间链——每条路只看自己类型的边。三条路不会互相干扰。最后把三条路的结果合在一起，按重要性排序。

## 五、局限性分析

### 5.1 扩散联想未生效

知识网的 37 条边全部是 `用户 → X` 的星形结构，节点之间没有互联：

```
当前知识网（星形）:
  用户 → 窗外云硕大洁白柔软
  用户 → 风和云的关系
  用户 → 白云变成了彩云
  （节点之间没有边——无法扩散）

理想知识网（网状）:
  窗外云硕大洁白柔软 ←→ 风和云的关系
  白云变成了彩云 ←→ 晚霞 ←→ 太阳要落山了
  云的味觉属性 ←→ 变成云朵的假设
```

**根因**：只有一天的数据，LLM 解析时产出的边都是 `agent → target`，没有产出节点间关联。这需要 Core 2（后台消化）在积累多天数据后，主动发现并建立节点间的语义关联。

> **通俗解释**：系统现在能认出"云"和"晚霞"都是聊过的话题，但还不知道它们之间有联系。就像一个刚认识你的人，记得你提过"下雨"和"理想国"，但还不知道这两件事是连在一起的。需要更多的对话和"后台消化"才能把碎片织成网。

### 5.2 单日数据局限

- 身份关系命中率低（1/15），因为一天内身份相关对话有限
- 没有跨天的时间链回溯（"昨天聊了什么"无法验证）
- 知识网节点间没有边，扩散激活无法验证

### 5.3 LLM 分类边界模糊

部分事件分类存在歧义。例如"关于这本书最深刻的记忆"——LLM 有时将其归为 `timeline`，有时归为 `identity`。这取决于单次 LLM 调用的判断，没有一致性保证。

## 七、结论

### 7.1 验证通过的设计

1. **三层结构"映射又独立"**：知识网、身份关系、时间链各自独立检索，互不污染，通过共享节点名互相引用
2. **LLM 自动分类有效**：Qwen3.5-9B 能稳定地将事件分为三类，分布合理（knowledge 39% / timeline 31% / identity 29%）
3. **子图扩散隔离噪声**：`spread_activation` 限定 `edge_type` 后，不再出现"百年孤独"被"我是小砂锅"淹没的情况
4. **查询路由正确**：所有查询结果都走对了层——"百年孤独"、"云"走知识网，"名字"走身份关系，"时间"走时间链

### 7.2 待验证的能力

- **知识网扩散联想**：需要多天数据 + Core 2 后台消化，建立节点间边
- **跨天时间链回溯**：需要连续多天数据
- **身份关系泛化**：从"你的名字"泛化到"你是谁" → "你是藤蔓"

### 7.3 下一步建议

| 优先级 | 方向 | 说明 |
|--------|------|------|
| P0 | 上规模（多天数据） | 用 7月13-19日一周数据，验证跨天时间链和知识网扩散 |
| P1 | Core 2 后台消化 | LLM 定期消化 prestore pool，产出节点间关联边，编织知识网 |
| P2 | 身份关系泛化 | 从离散的身份事件中提取稳定的身份模型（"我是藤蔓，我是 AI，我不是主人"） |
| P3 | 遗忘与衰减 | 时间链天然衰减（越远越模糊），知识网需要基于引用频率的权重衰减 |

### 🔍 深度评估：M9 三层记忆结构的实验价值

#### 1. 架构评估：从“数据库思维”到“认知拓扑”的跨越
M9 最大的贡献不在于检索准确率的提升，而在于它**在工程上强制实现了认知科学的同构**。

-   **结构性胜利**：M8 的失败是必然的，因为它是“扁平化存储+后期过滤”的思路（类似传统 RAG）。M9 将分类前置到了**写入时（Write-time）**而非读取时（Read-time）。这意味着 LLM 在解析消息的那一刻，就在执行“认知编码”而非简单的“信息抽取”。这是从 *Information Retrieval* 向 *Cognitive Architecture* 的关键一步。
-   **关于“星形结构”的重新定性**：报告中将知识网的星形结构视为“局限”，但在单日数据的冷启动阶段，这其实是**正确的中间态**。人类在学习新领域的第一天，也是以“自我/当前上下文”为中心建立孤立节点的。星形结构不是 bug，而是知识网编织前的“原材料堆积态”。**Core 2 的本质任务，就是将这些星形簇转化为网状流形。**
-   **隔离即保护**：三层独立不仅是为了防污染，更是为了**支持异构的遗忘机制**。时间链应该遵循艾宾浩斯衰减；身份关系应该是“高阈值、低衰减”的固化结构；知识网则应遵循“使用频率+语义关联度”的动态权重。M9 的物理分层为未来实现这三种完全不同的神经动力学奠定了基础。

#### 2. 风险预警：开放实验中可能遇到的“隐形天花板”
在无工程约束的探索中，以下问题比当前的命中率更值得警惕：

-   **LLM 分类器的“语义漂移”**：目前 Qwen3.5-9B 的分类分布看起来很完美（39/31/29），但这可能是小样本下的巧合。随着对话深入，边界案例会激增。例如：“我记得你说过你喜欢云”——这既是时间链（记得...说过），又是知识网（喜欢云），还是身份关系（你的偏好）。**当一条消息同时激活三层时，当前的“单选”或“简单多选”机制是否会丢失信息的纠缠态？** 建议考虑引入“边权重”或“跨层链接”来表达这种模糊性，而不是强行归类。
-   **节点粒度的“巴别塔问题”**：`窗外云硕大洁白柔软` vs `窗角洁白柔软的硕大云朵`。在知识网中，这两个节点语义相同但字面不同。如果 Core 2 不能做**实体对齐/概念归一化**，知识网就会变成一堆无法收敛的字符串碎片。这不是检索问题，是**本体论构建**问题。建议在 P1 优先级中显式加入“节点合并/归一化”步骤。
-   **时间链的“伪时序”陷阱**：当前的时间链是基于“消息到达顺序”还是“事件发生顺序”？用户说“我昨天去了公园”，这条消息在今天产生，但它描述的是过去。如果时间链只记录 log timestamp，它就退化成了聊天记录列表。**真正的情节记忆需要“双重时间戳”（叙述时间 vs 事件时间）**，否则无法回答“上周发生了什么”这类涉及时间推理的问题。

#### 3. 下一步实验建议：超越“准确率”指标
既然是开放实验，建议暂时放下“命中率”这种工程 KPI，转向更具探索性的观测指标：

| 建议方向 | 具体实验 | 预期洞察 |
| :--- | :--- | :--- |
| **拓扑相变观测** | 持续喂入 7 天数据，绘制知识网的“平均路径长度”和“聚类系数”随时间的变化曲线 | 观察知识网何时从“星形集合”相变为“小世界网络”。这个临界点就是 Core 2 生效的标志。 |
| **跨层共振测试** | 故意构造需要三层联合才能回答的问题：“那个喜欢云的AI（I+K）昨天说了什么（T）？” | 验证三层之间的“节点名共享”是否足以支撑复杂推理，还是需要显式的跨层边。 |
| **主动遗忘实验** | 人为注入矛盾信息（先说“我是藤蔓”，后说“我是石头”），观察系统的冲突解决机制 | 记忆不仅是记住，更是“选择性忘记”。没有遗忘机制的记忆系统最终会被噪声淹没。 |
| **LLM 作为“海马体”** | 让 LLM 在解析时输出 confidence score，低置信度的事件进入“短期缓冲池”，高置信度的直接写入长期图 | 模拟人脑的“编码-巩固”两阶段过程，减少错误记忆的形成。 |

### 💡 总结性判断

> **M9 不是一个“更好的搜索引擎”，它是一个“初级认知器官的原型”。**

在当前阶段，它的价值不在于查得准不准，而在于它**证明了三层分离在工程上是可行的，且在认知上是合理的**。星形结构、单日数据、分类模糊——这些都不是失败，而是这个有机体在“婴儿期”的正常特征。

**给实验者的建议**：保持现在的“诚实记录”风格。不要急于优化命中率去迎合某种 benchmark。继续喂养数据，观察拓扑的自然生长，记录那些“意外”的发现（比如某个节点突然成为了意想不到的枢纽）。在这个无约束的实验场里，**异常值比平均值更有价值**。

这份报告本身已经是该实验里程碑级的产出。建议将其作为 v0.9 基线存档，后续所有演化都以此为锚点进行对比。
